# The strategy read-API: a scoped `Portfolio` seam returning frozen `PositionView`/`AccountView` snapshots

_Accepted via the D8 grilling session on decision ticket [#135](https://github.com/MarcosACH/tickwright/issues/135), part of the trade-economics map [#107](https://github.com/MarcosACH/tickwright/issues/107). Fixes the method set and scoping rules of the `Portfolio` Protocol that ADR-0035 (D2) placed in `domain` and left open; exposes exactly the Tier-1/Tier-2 numbers ADR-0034/0036/0037/0040 define; consumes the mark ADR-0039 (D6) put on the feed; and honors the ambient account of ADR-0038 (D5). It also **refines ADR-0040 §2** — the per-position `effective_leverage` denominator._

`Portfolio` is the first **pull-state** seam ever handed to a strategy (strategies are push-only today: `on_tick`/`on_order_event`). This ADR fixes its shape: **a handful of synchronous methods returning frozen `domain` value snapshots**, scoped to the calling strategy, over the one `engine` `PortfolioProjection`.

## 1. Return shape: frozen aggregate views, not granular scalars

Reads return **frozen `domain` value objects** — `PositionView` and `AccountView` — whose fields *are* the quantities, not one accessor method per scalar. The decisive property is **internal coherence by construction**: every field of a view is computed from a *single* read of `(position, mark)`, so `unrealized_pnl` and `notional` in one view can never straddle a fill. This satisfies the "frozen values, not dicts" grain, keeps the `domain` Protocol tiny (three methods, not ~15), and reuses the `Position`/`Account` value model of ADR-0035. A granular-scalar surface is rejected: it delivers loose scalars whose mutual coherence a reader must reason about, and it explodes the seam into ~15 compile-time dependency points.

**The views are distinct types from the mutable `Position`/`Account` aggregates.** The aggregates carry `apply()` and mutate under the reader on the next fill; handing one out would break the frozen-snapshot coherence. So the seam returns read-only copies (`@dataclass(frozen=True)`) computed at read time. Named `*View` (CQRS read-model idiom) rather than `*Snapshot` to avoid overloading the existing `Strategy.snapshot() -> bytes` (state serialization, ADR-0016).

No monolithic all-in-one `snapshot()` method: sync reads (§7) have no `await` point, so two reads inside one handler cannot straddle a fill, making cross-view coherence hold **without** a bundle.

## 2. Scope: own attribution at position grain, the shared pool for the account

The seam serves **two grains at once**, and is **scoped to the calling strategy at injection** — a per-strategy facade bound to its `strategy_id`, mirroring the `SignalEmitter(strategy_id=…)` each strategy already receives (`single_shot.py:41`). Methods therefore take **no** `strategy_id`, `venue`, `account_id`, or `currency` argument — the account is ambient (one per process, ADR-0038) and USDC-settled (ADR-0029), and a strategy structurally cannot read another's attribution.

- **Position grain — the strategy's own overlay.** `position(symbol)` / `open_positions()` return `PositionView`s whose **own-attribution slice** (§4) is built from the fills *this* strategy placed; their **position-grain economics** (§4) describe the whole venue position and are not attributable to a strategy at all. In v1 (`NET`, disjoint `(strategy, symbol)` per account, ADR-0034) each symbol has exactly one owning strategy, so the own-overlay **numerically equals** the account net for that symbol — the scoping is a `HEDGE`-ready boundary that is exact today, not a v1 cost. The one v1 case where they differ is **foreign flow** on the strategy's symbol (§5).
- **Account grain — the honest shared pool.** `account() -> AccountView` returns the account-wide aggregate (equity, cash, total margin, free margin), **not** filtered to the strategy, because collateral is one pool. This is *how* a strategy reaches margin/equity numbers — a separate method at the honest grain, never a scope argument.

The attribution footgun (handing a strategy account-level realized PnL that secretly mixes another strategy's flow, ADR-0040 grain rule) is avoided because **realized PnL lives only on the per-strategy `PositionView`**, never as an `AccountView` field; `AccountView.cash`/`equity` are account-wide sums labeled as what they are.

v1 exposes **no separately addressable account-net `PositionView`**: the account net per symbol already exists internally (ADR-0034/0035's reconciliation anchor) and feeds the position-grain fields of §4, but a *whole-position* view — account-net `size`/`entry_price`/`realized_pnl` beside the strategy's own — is a `HEDGE`-era additive accessor, not v1 code. In disjoint-`NET` without foreign flow its attribution fields would be a redundant alias of the own-overlay; under foreign flow they are exactly the decomposition §5 deliberately withholds from a strategy.

## 3. The method set

A three-method `domain` Protocol, all synchronous (§7), no mark argument (the projection holds the latest mark internally, ADR-0039):

```python
@runtime_checkable
class Portfolio(Protocol):
    def position(self, symbol: str) -> PositionView | None: ...
    def open_positions(self) -> tuple[PositionView, ...]: ...
    def account(self) -> AccountView: ...
```

**Positions are standing records** (P1 #119: the aggregate retains cumulative realized after a full close). So the seam distinguishes:
- **Never traded** → `position(symbol)` returns `None`.
- **Flat with history** (fully closed) → a `PositionView` with `size=0`, `entry_price=0`, but `realized_pnl`/`fees`/`funding` retained; **excluded** from `open_positions()` (which returns only `size != 0`).

**On a flat record the position-grain half (§4) degenerates.** When the symbol's **account-net** position is also flat: `notional`, `margin_used` and `maintenance_margin` read `0`; **`liquidation_price` reads `None`** — ADR-0040 §3's paper formula is undefined at `size = 0` (it divides by size, and `side` has no sign on a flat position), and `None` is exactly what the live path reports for a position the venue no longer holds (ADR-0040 §3: `None` when the venue omits it), so the two paths stay identical (ADR-0034) instead of paper inventing a value. `effective_leverage` follows §4.1 with no special case: `0` for a **cross** position on a positive-equity account (zero exposure over real equity), `None` for an **isolated** one, whose released collateral leaves the denominator at `0`. If the strategy is flat while **foreign flow** still holds the symbol, the account net is *not* flat and the position-grain fields read that venue position's real values (§5).

This lets a strategy read its lifetime realized on a since-closed symbol (`position("BTC").realized_pnl`) and keeps "flat" honestly distinct from "never here". A strategy knows its own declared symbols, so no "list every record I ever touched" method is needed in v1.

## 4. The view field sets

Every money and size quantity is `Decimal` (ADR-0029); the three exceptions are `leverage` (an `int`, §4.1), `mark_ts` (an `int` UTC epoch ns, §6) and `margin_mode` (the `cross`/`isolated` mode of ADR-0040 §1). `PositionView` carries **two grains**, which in v1 usually coincide but diverge under foreign flow (§5), so the split is explicit:

- **Own-attribution slice (the strategy's `strategy_id` partition)** — `size`, `entry_price`, `realized_pnl`, `unrealized_pnl`, `fees`, `funding`. The numbers a fill partitions linearly or attributes (ADR-0034/0040 grain rule + P1 #119).
- **Position-grain economics (computed off the symbol's account-net `szi`, not the strategy's own size)** — `notional`, `leverage`, `margin_mode`, `margin_used`, `maintenance_margin`, `liquidation_price`, `effective_leverage`, and `mark_ts` (§6). These are properties of the *whole* venue position — one collateral bucket, one `liquidationPx` — which the venue keys per position, never per strategy.

| `PositionView` | `AccountView` (account-wide pool) |
|---|---|
| *own slice:* `size`, `entry_price` | `equity` (`= cash + Σ uPnL`) |
| *own slice:* `realized_pnl`, `unrealized_pnl` | `cash` (Tier-1 collateral balance) |
| *own slice:* `fees`, `funding` | `total_margin_used` (Σ) |
| *position-grain:* `notional`, `leverage`, `margin_mode` | `total_maintenance_margin` (Σ) |
| *position-grain:* `margin_used`, `maintenance_margin` | `free_margin` (`equity − total_margin_used`) |
| *position-grain:* `liquidation_price`, `effective_leverage` | `effective_leverage` (`total_notional / equity`) |
| *position-grain:* `mark_ts` (§6) | *(no account `liquidation_price` and no account `mark_ts` — staleness is judged per-position)* |

Venue-faithful placement (R3 #110): the venue reports `leverage`, `liquidationPx`, `marginUsed`, `positionValue`, `unrealizedPnl` **per position** (`clearinghouseState.assetPositions[].position`), and `accountValue`/`totalMarginUsed`/`withdrawable` **account-wide** (`marginSummary`). There is **no** account-level liquidation price. `PositionView.maintenance_margin` is computed (`notional × margin_maint`) — the venue has no per-position maintenance field, so only the account Σ has a venue value to cross-check (ADR-0040 §6). The raw mark **value** is not a `PositionView` field (only its freshness `mark_ts`, §6); ADR-0039 keeps the mark an accounting input, not a strategy signal.

### 4.1 `effective_leverage` denominator — refines ADR-0040 §2

`effective_leverage` is the **realized** ratio (exposure ÷ backing equity), distinct from `leverage` (the **set nominal cap**, an integer that fixes the initial-margin fraction `1/leverage`). ADR-0040 §2 fixed the per-position denominator as account `equity`; that is wrong for an **isolated** position and is corrected here:

- **isolated position:** `effective_leverage = notional / (isolated_collateral + unrealized_pnl)`
- **cross position:** `effective_leverage = notional / account_equity`
- **account:** `effective_leverage = total_notional / account_equity`

**A non-positive denominator reads `None`** (§6): equity can reach `0` (a live account whose ingested genesis is itself `0` — ADR-0042 §6 — before its first trade) and go negative (losses past genesis — ADR-0040 §7 reports that state without rejecting or liquidating), and an isolated position's `isolated_collateral + uPnL` passes through `0` at its liquidation point and negative beyond. A wiped or negative backing equity has no meaningful exposure ratio, and dividing anyway is worse than useless: `Decimal` raises on a zero denominator, and a negative one returns a *negative* leverage that reads as safely deleveraged.

The isolated denominator is the position's backing collateral plus its unrealized PnL (`isolated_collateral + uPnL`, both position-grain per §4). R3 §2.3 lists `isolated position equity = leverage.rawUsd + unrealizedPnl` under **"Inferred / needs confirmation — field algebra the venue docs do not spell out"**, and R3 §1.3 hands the exact denominator (whole-account equity vs per-position isolated equity) to this ADR as a **modelling choice to confirm** — so it is adopted here **on argument, not as a venue-confirmed fact**, and its validation against a funded testnet position is added to #142's scope. The argument: only a position-grain denominator makes the defining behavior hold — adding isolated margin (`updateIsolatedMargin`, live-only; paper freezes collateral at open, ADR-0040 §1) raises the collateral → drops `effective_leverage` and pushes `liquidation_price` away, whereas an account-equity denominator would leave `effective_leverage` unmoved by the top-up. `effective_leverage` remains convention-only and **outside** the §6 alert band (no venue field to compare).

**(Confirmed by [#142](https://github.com/MarcosACH/tickwright/issues/142) — the modelling choice is right; R3's `rawUsd` identification is not.** The defining behaviour was reproduced against the venue: an `updateIsolatedMargin` top-up of +20 USDC drove `effective_leverage` from `129.588/25.856067 = 5.0119` to `129.588/45.856067 = **2.8260**`, and pushed `liquidation_price` from `52522.4977` out to `42395.9154`. An account-equity denominator would have left both untouched, so this ADR's correction of ADR-0040 §2 holds.

What does **not** survive is R3 §2.3's arithmetic for it. `leverage.rawUsd` measured **`−103.731933`** on that position — it is the cash leg net of cost basis, negative for a long, not the collateral (see the ADR-0040 §3 correction). The denominator is the position's backing collateral plus its unrealized PnL (`isolated_collateral + uPnL`), and the venue field that *equals* it is **`marginUsed`**, never `rawUsd`. That is an **identity, not a sourcing rule**: the denominator stays **computed** off our own mark like every other Tier-2 number (ADR-0040 §3 — the venue's `marginUsed` is the divergence cross-check, not the input), and live obtains its `isolated_collateral` term as `marginUsed − unrealizedPnl` (ADR-0043 §3). The two sides therefore differ by the mark skew ADR-0040 §6's band exists to absorb — which is exactly why isolated `margin_used` now sits *inside* that band. So the denominator as written here is correct, and only R3's field algebra for it changes.**)**

## 5. The unattributed partition stays off the seam

The `strategy_id=None` partition (foreign flow — a manual venue-UI trade or a pre-existing position, ADR-0038) is **not reachable** on the strategy-facing seam: a strategy's facade is bound to its real `strategy_id`, and `None` is not a strategy. So the **own-attribution fields** (§4) return only the strategy's own flow — if strategy `S` holds BTC `+2` and foreign flow adds `+1` (`szi = +3`), `S.position("BTC").size` reads `+2` and `realized_pnl`/`unrealized_pnl`/`fees`/`funding` are its `+2` slice. The **position-grain fields** (§4), however, read the whole venue position: `notional = 3 × mark`, and `margin_used`/`liquidation_price`/`effective_leverage` are the `+3` position's (one collateral bucket, one `liquidationPx`) — because those are properties of the venue position, not a strategy's slice, and splitting them would understate a safety-relevant number. The foreign flow's effect is thus **honestly present** in both the position-grain fields and the account-level numbers (`equity`/`cash` fold in the full `szi`); only the *attribution* of the `+1` to a strategy is withheld. The unattributed partition is an engine/telemetry concern (reconciliation, ADR-0038 account-exclusivity alerting), surfaced via the `engine` concrete (§8), never the `domain` seam — keeping ADR-0038's "no strategy's PnL is polluted by exposure it did not open" structural.

## 6. Nullability: absent marks read `None`, staleness is exposed

ADR-0039 deferred its `None`-surfacing to this ticket, with the policy: a **stale** mark freezes at its last value; a **wholly-absent** mark reads `None` (never a fabricated flat); **no per-read max-age** (the read path is clock-free — the strategy/reconcile judges staleness). Applied to the field types:

- **Tier-1 fields are never `None`** — `size`, `entry_price`, `realized_pnl`, `fees`, `funding`, `cash`. Readable even in the recovery window before any mark. (`isolated_collateral` is Tier-1 as well — the locked amount itself: an ingested position *input*, mark-independent, persisted per ADR-0043 §3 — but it is a **projection input, not a `PositionView` field**. §4's position-grain set does not carry it, and this bullet enumerates what the *seam* returns.)

  **(Amended by [#142](https://github.com/MarcosACH/tickwright/issues/142).** This bullet originally listed isolated **`margin_used`** here, on ADR-0040 §3's since-corrected claim that it "equals that collateral by definition". Measured against the venue, isolated `margin_used` is `isolated_collateral + unrealized_pnl` and **moves with the mark**, so it is Tier-2 and belongs in the next bullet. Only the underlying `isolated_collateral` is Tier-1 — which is what ADR-0043 §3 persists, so that decision is unaffected. The practical consequence is that an all-isolated position now reads `margin_used` as `None` before its first mark, where this ADR previously promised a real `Decimal`.

  Note what that costs the **seam**, since the two are easily conflated: `margin_used` was the only `PositionView` field carrying an isolated position's locked collateral, so with it Tier-2 the view has **no Tier-1 read of that collateral at all** in the recovery window. `isolated_collateral` does not fill the gap — it is persisted and mark-independent, but §4 does not put it on the view, so a strategy cannot reach it. Exposing it is recorded as a named extension point in *Consequences* rather than taken here: this amendment corrects facts and reopens no decision, and widening the seam's field set is one.**)**
- **Tier-2 mark-dependent fields are `Decimal | None`**, `None` when the mark is absent: `unrealized_pnl`, `notional`, `margin_used` (**both** modes — cross as `notional / leverage`, isolated as `isolated_collateral + unrealized_pnl`; #142), `maintenance_margin`, `effective_leverage`, paper `liquidation_price` (live `liquidation_price` is separately `None` when the venue omits it; **both** are also `None` on a flat account-net position, §3; and `effective_leverage` has one further non-mark case, below). The condition is per-**term**, exactly as for the account Σs below: a field is `None` only when the mark is absent **and its own terms need it**. On a flat position they do not — a flat *account-net* position reads `notional`, `maintenance_margin` and `margin_used` (in **either** mode) as `0` with or without a mark (§3), and a flat *own* slice reads `unrealized_pnl` `0` — because `|0| × mark` and `0 × (mark − entry)` need no mark, and a flat *isolated* position's `isolated_collateral + unrealized_pnl` is `0 + 0` for the same reason: its collateral is released with the position (§3, which reads the released denominator off the same fact). The seam **surfaces** the `None`; the strategy handles it — primarily a cold-start/recovery transient, since once a mark lands it freezes-on-stale and never returns to `None`. (The flat-position clause read "**cross** `margin_used`" until [#142](https://github.com/MarcosACH/tickwright/issues/142) — a qualifier that was load-bearing only while isolated `margin_used` was Tier-1 and outside the mark question entirely. With it Tier-2, the exemption applies in both modes, and §3's unqualified "`margin_used` … read `0`" is what holds.)
- **Every account Σ over a mark-dependent per-position quantity is `Decimal | None`** — `equity`, `total_margin_used`, `total_maintenance_margin`, `free_margin`, `effective_leverage` — `None` iff a **contributing term** is itself mark-dependent and unavailable (a cross-strategy coupling: one un-marked symbol makes the account-equity read `None` for every strategy, because account equity is genuinely uncomputable then). The condition is per-term, not per-position — though for `total_margin_used` that no longer buys an exemption: per-position `margin_used` is mark-dependent in **both** modes (#142, above), so it goes `None` whenever *any* held position lacks a mark. **All four Σs** now have a mark-dependent term in every mode; the earlier claim that an all-isolated account (ADR-0040 §1's primary mode) always reports a real total does not survive the measurement. **`cash` is exempt outright** (Tier-1), so cold-start is not a blackout.
- **`effective_leverage` has one further `None` case, unrelated to the mark: a non-positive denominator** (§4.1). Per-position and account alike, it is `None` when its backing equity is `≤ 0` — the only Tier-2 `None` a fresh mark does not cure. Every other Tier-2 field stays a real `Decimal` there (`notional`, `unrealized_pnl` and the margins are all well-defined on a wiped account); this one is `None` because the ratio itself is undefined, not because an input is missing.
- **Staleness is exposed, not decided by the seam.** `PositionView` carries `mark_ts: int | None` (UTC epoch ns) — the observation time of the mark the projection holds (ADR-0039); the raw mark **value** is not exposed (ADR-0039: the mark stays an accounting input, not a strategy signal). `mark_ts is None` ⟺ the mark is absent ⟹ every mark-dependent Tier-2 field **whose own terms need the mark** reads `None` (a flat position's do not — above; the converse holds for all of them but `effective_leverage`, which is also `None` on a non-positive denominator); a *stale* mark has an old `mark_ts` with Tier-2 fields computed off the frozen value. The strategy — which holds a `Clock` — compares `mark_ts` to `now` to judge "too stale". Without `mark_ts`, a strategy would have no way to detect a stale-but-present mark, so it is load-bearing.

## 7. Synchronous, and injected by the composition root

**Sync methods.** Reads recompute Tier-2 from in-memory `(position, mark)` (ADR-0035) and do no I/O (ADR-0004 keeps any venue call off this path), so an `async def` would be a lie. It is also load-bearing for §1 coherence: a synchronous read has **no `await` point**, so no fill-apply task can interleave between two reads in one handler. (Precedent: the `Clock` seam mixes sync reads with async waiters.)

**Constructor injection from the composition root — no `Strategy` Protocol change.** The `Clock`/`EventBus` are passed into a strategy's `__init__` by `build_engine`, not set by the engine and not on the `Strategy` Protocol; `build_engine` constructs the projection *and* the strategies, so it hands each strategy a scoped `Portfolio` facade (e.g. `projection.for_strategy(strategy_id)`) the same way. The `Strategy` Protocol stays a minimal structural seam (push handlers + `set_next_seq`/`snapshot`/`restore`); a strategy that reads no portfolio simply omits the arg. A new Protocol member or engine-set attribute is rejected — it forces the seam on every strategy and raises a "when is it set during recovery?" question constructor injection never has.

**Lifecycle reads.** Before the first fill: `position(symbol)` → `None`, `open_positions()` → `()`, `account()` → genesis (`equity = free_margin = cash = genesis`, margins `0`, all real `Decimal`s **on a positive genesis** — zero positions means nothing mark-dependent). The one exception is a **zero** genesis: account `effective_leverage` is then `None`, its denominator being `0` (§4.1) — a non-mark `None` in a window otherwise free of them. **(Amended by ADR-0042:** this once cited a zero genesis as ADR-0040 §7's supported *config*. ADR-0042 §1 makes a configured zero unreachable on paper (`gt=0`, no default), so the case survives on the **live** path only, where genesis is ingested as `accountValue − Σ uPnL` (ADR-0042 §6) and reads `0` for a wallet that opens unfunded. The seam behavior is unchanged — only the reachability argument is.**)** During recovery, before the first reconcile (ADR-0034's freeze-never-flat window): Tier-1 reads the restored snapshot (honest last-known `size`/`entry`/`realized`/`cash`, possibly stale until reconcile heals it — **never a fabricated flat**); Tier-2 is `None` until the first post-restart `MarkTick` — on the **open** positions. A restored *flat* record is unaffected: its position-grain fields degenerate per §3 throughout the window — by §6's per-term condition, a flat position's valuations need no mark. (Its `effective_leverage` still follows §4.1, so a flat **cross** record reads `None` here rather than §3's `0`, account `equity` being itself `None` while an open position lacks a mark.) The seam carries **no "recovery in progress" flag** — whether a strategy is gated from trading until reconcile completes is a lifecycle concern owned by the durability ticket [#137](https://github.com/MarcosACH/tickwright/issues/137), not a `Portfolio` field. This ticket fixes only what the seam *reports* inside the window. **(Answered by ADR-0043 §6: there is no gate.** The residue the window leaves is confined to `account()` accuracy — the order barrier already heals own-flow through the fill-apply path, and `position()` reads only the strategy's own overlay — and gating *trading* on a *reporting* surface would breach the map's enforcement ceiling. The window opens at `host.start()` and closes at the first ledger reconcile cycle. No `on_tick` can fire inside it (the feed starts last), but `on_order_event` **can** — the reconcile cadences publish into it — so a strategy that emits from its order-event handler places while reading exactly the Tier-1 this section specifies: restored, honest, possibly stale, never a fabricated flat.**)** ADR-0043 §6 also removes the one case where this section's "`cash` is never `None`" promise could have broken: a live first run now materialises the account row inside the startup barrier, rather than at a reconcile cycle that fires after strategies start.

## 8. Other consumers: `domain.Portfolio` is strategy-only

The `domain` `Portfolio` Protocol exists for **dependency direction** — so a `domain` strategy compiles against a `domain` seam instead of importing `engine` (ADR-0035) — and is shaped **only** by strategy needs. Telemetry, the CLI, reconciliation, and a future read-only guard all live in `engine`/`app` and read the **`engine` `PortfolioProjection` concrete directly**; they do not need the `domain` indirection. The projection can expose a broader account-wide surface for them (every per-strategy partition *and* the `None` unattributed slice, the account-net-per-symbol aggregate, a foreign-flow signal for the ADR-0038 account-exclusivity alert) — reads a strategy must never make. Reconciliation is the projection's own healing loop, not an external seam consumer. Portfolio-**risk** enforcement stays out of scope (ADR-0035 defers the `RiskEngine`). The concrete telemetry/observability read surface is a **deferred, additive extension point**, not specified here; this ADR fixes only the boundary (the `domain` Protocol is strategy-only).

## Consequences

- **Additive and dependency-safe** — a new `domain` Protocol (`Portfolio`) plus two frozen `domain` value types (`PositionView`, `AccountView`); the `Strategy` Protocol is unchanged; strategies keep depending on `domain` alone.
- **Delivers the strategy read-API ADR-0035 unblocked** — the exact method set and scoping the `Portfolio` seam left open.
- **Refines ADR-0040 §2** (§4.1) — the per-position `effective_leverage` denominator is the position's backing collateral plus its unrealized PnL for isolated (a modelling choice R3 flagged for confirmation, **since confirmed** by [#142](https://github.com/MarcosACH/tickwright/issues/142) against a funded position — §4.1), and it is **nullable on a non-positive denominator** — the one Tier-2 `None` no mark can cure; ADR-0040 §2 (definition + nullability) and the CONTEXT.md **Leverage & Margin mode** term are corrected in-place (docs-sync).
- **Refines ADR-0039** (§6) — the mark stays unexposed as a value; only its freshness `mark_ts` rides `PositionView` pull-style. ADR-0039's "Strategies do not see the mark" section and its deferred `None`-surfacing / startup-gap sites are amended to point forward; ADR-0035's *Consequences* ("method set is specifiable") and ADR-0040 §2's "how a strategy reaches account-level numbers" are back-linked to this ADR (docs-sync).
- **Adds CONTEXT.md terms** — `PositionView`, `AccountView`; the `Portfolio` term is sharpened with the method set and scoping.
- **Deferred, named extension points** — the account-net-per-symbol accessor (`HEDGE`/multi-strategy), the telemetry/observability read surface on the `engine` concrete, an `on_mark` strategy callback (ADR-0039, kept a zero-rework extension), and **`PositionView.isolated_collateral`** — Tier-1 and persisted (ADR-0043 §3) but deliberately off the seam per §4. [#142](https://github.com/MarcosACH/tickwright/issues/142) moving `margin_used` to Tier-2 (§6) leaves a strategy with no recovery-window read of an isolated position's locked collateral; exposing the field would restore it, and is left to whoever finds they need it rather than decided by a fact-correction.
- **The recovery trading-gate** — whether a strategy may act before reconcile completes — is left to the durability ticket [#137](https://github.com/MarcosACH/tickwright/issues/137).
