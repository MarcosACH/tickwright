# The accounting surface is a `domain` Position/Account model behind a `Portfolio` read seam, projected in the `engine`

_Accepted via the D2 grilling session on decision ticket [#112](https://github.com/MarcosACH/tickwright/issues/112), part of the trade-economics map [#107](https://github.com/MarcosACH/tickwright/issues/107). Builds on ADR-0034 (D1); downstream map tickets, the PRD, and implementation build on it._

The accounting surface decomposes into a small **`domain` value model** — `Position` and `Account` — read through a **`Portfolio` Protocol** and maintained by a single **`engine` projection, `PortfolioProjection`**, the economic sibling of the order `Cache` (ADR-0009). It is a **separate** projection, not an extension of the order `Cache`: the order read-model is keyed by `cloid` against the order `Store`, whereas the accounting read-model is keyed by position and reconciled against a different venue anchor (the account/position snapshot, not open orders). One responsibility each keeps the ≤2-implementations grain (ADR-0032).

## Decomposition: a layered value model, not a monolith

`Position` and `Account` are pure `domain` aggregates with no I/O — the same shape as the order-FSM `Order` (ADR-0009): a **mutable idempotent `apply(...)`** that accumulates exact state (tracking applied-event ids, ADR-0025), plus **pure query methods** that recompute valuations from a mark. Keeping the average-cost algorithm a pure unit makes it property-testable in isolation (the position/PnL prototype, [#119](https://github.com/MarcosACH/tickwright/issues/119)) and turns the two-level topology into a *keying* concern rather than branching inside one class. A monolith collapses the seams and buries the reconciliation-anchor boundary.

## Position keying and the reconciliation anchor

- **`Position` is keyed per `(account, strategy, symbol)`** — the finest grain. It carries the Tier-1 ledger (signed size, average entry, realized PnL, accrued fees/funding, cash) and recomputes Tier-2 valuations (unrealized PnL, notional) from a mark (ADR-0034). **ADR-0038 refines this**: the account is a deployment fact (one account per process), so `(account, …)` is the *logical* key while the materialized runtime key is `(strategy, symbol)` — identity yes, key no — and `strategy` is `str | None`, `None` being the reserved unattributed partition.
- **The account-level net is a computed aggregation, not a stored object.** On the v1 `NET` venue with disjoint `(strategy, symbol)` per account (ADR-0034), each symbol has exactly one owning strategy, so `Σ(Position size per symbol)` is a one-term sum that must equal the venue `szi`. The **independent check that gives ADR-0034's Σ-invariant teeth is the venue itself** (or the paper exchange's own net) — reconciled every cycle — not a second internal projection that would apply identical fills to an identical position and only ever agree with itself.
- **A distinct account-net position with its own fill-application** — the only thing that behaves differently from Σ, and only when cross-strategy netting reclassifies realized/unrealized PnL — is the documented **`HEDGE`/multi-strategy extension point**, not v1 code. This refines ADR-0034's "one net position" to "the aggregation, which is trivially one position in v1's disjoint world"; the two are the same computation wherever v1 operates.
- **`Account` is a stored aggregate** — cash/collateral (Tier-1) plus reported margin, effective leverage, and liquidation price (Tier-2, recomputed) — the boundary that maps to the venue's account snapshot. Its identity and netting semantics are venue-declared through `AccountSpec` on the `Exchange` Protocol (ADR-0038), the peer of `instrument_specs()`; `AccountSpec` is to `Account` as `InstrumentSpec` is to the instrument.

## Feed: synchronous on the execution path, recomputed on read

- **Tier-1 is written synchronously on the fill-apply path, in one transaction with the order checkpoint.** The same `ExecutionManager` step that checkpoints the order `Cache` also applies the fill to the `PortfolioProjection` — **store-first, then project, before the fill is published** on the bus. **ADR-0043 §4 makes the store step atomic**, not merely ordered: the order row and the ledger rows are written by a single `Store` call in one transaction, because either split ordering loses or double-counts a fill across a crash — and on paper, where `PaperExchange` persists nothing, no reconcile exists to heal it. The surface is **not** a bus subscriber, so a fill is applied **exactly once** (no double-count from also hearing it), and the two projections move atomically from any reader's view — a reader never sees the order `FILLED` while its position is still stale. Funding accruals (on the `Clock` cadence) and reconciliation synthetic events converge on the **same idempotent `apply()`** (ADR-0034). **ADR-0042 §4 closes the cash line's write-set** to exactly four **accruing** inputs — genesis, `+` realized PnL, `−` fees (ADR-0036's `fee > 0` is a cost debited), `+` funding — so what may *move* `cash` by accrual is enumerable and enforceable; deposits, withdrawals and transfers are not modelled on either path. The reconciler's synthetic cash adjustment (ADR-0034) is not a fifth input but a live-only **correction** toward venue truth, and converges on the same `apply()` as everything else here.
- **Tier-2 is recomputed on every read** from `(current position, ingested mark)` — never stored, and with **no memoized cache** in v1. Clarity over valuation throughput for a reference implementation; a mark-invalidated memo is a documented performance-extension point.
- **Reads are method calls, never PnL subscriptions** (ADR-0004): a strategy queries a snapshot through the `Portfolio` seam.

## Placement (ADR-0032)

- **`domain`** holds the `Position` and `Account` types and the **`Portfolio` Protocol** — the strategy-facing pull seam, alongside `Exchange`/`Store`. The one-impl `Portfolio` Protocol exists for **dependency direction** (a strategy compiles against a `domain` seam, never an `engine` concrete — and strategies are today push-only, so this is the first pull-state seam handed to them), **not** for swappability: there is deliberately **one** projection with identical paper/live compute (ADR-0034). Economic metadata **extends `Instrument spec` additively** (`maker_fee`/`taker_fee`/`margin_maint`/`max_leverage`, ADR-0017/0030 — the `margin_init` this list once anticipated is **dropped by ADR-0040 §4**, the collateral **moved in at open** being `notional / leverage` off the per-symbol configured leverage, not static metadata); the fill event grows a fee field and a funding event joins the catalog (ADR-0025).
- **`engine`** holds `PortfolioProjection` — core machinery like `Cache`/`reconcile`, **not** a swappable adapter, so **no new top-level package** (ADR-0032 reserves those for venue adapters and seam impls). It pairs with the existing `Store` seam (durable ledger; schema/cadence deferred to the durability ticket) and is fed by the `ExecutionManager`.
- The concrete folder tree (module names, any subpackage) is a **`/module-map` artifact**, as ADR-0032 requires — only the dependency direction, the extension unit, and the wiring are fixed here.

## Naming

`Position`, `Account`, `Portfolio` (Protocol), `PortfolioProjection` (impl). **"ledger" stays an informal descriptor** for Tier-1 accumulated state — never a class name (the `drain_ledger`/absence-tracker uses of the word stand). **`Cache` stays the order read-model.** Only the **structural** terms are settled here; the economic-quantity vocabulary (`Equity`, realized/unrealized `PnL`, `Margin`, `Funding`, `Fee`, `Mark price`, `Collateral`) is defined by its owning model tickets ([#116](https://github.com/MarcosACH/tickwright/issues/116) fee, [#117](https://github.com/MarcosACH/tickwright/issues/117) funding, the margin/mark tickets) plus a terminology sweep — their mechanics are still open, so a definition written now would drift from what those tickets land. (**Delivered** by those tickets' ADRs and the ADR-0045 sweep ([#138](https://github.com/MarcosACH/tickwright/issues/138)); the deferral was vindicated — the sweep found four places the documents had already drifted from each other, ADR-0045 §9.)

## Consequences

- **Delivers ADR-0017's Open Q#17** ("Portfolio / positions tracker", deferred): `Portfolio` **is** that tracker — the *reported-accounting* part of it. Portfolio-**risk** enforcement (exposure/max-position limits, the `RiskEngine`) stays deferred and out of this map's scope. Docs-sync to ADR-0017 when the implementation lands — the same deferred-docs-sync discipline ADR-0034 applies to its ADR-0018 caveat.
- **Unblocks the strategy read-API ticket** (ADR-0034 named it as waiting on this): the pull surface is now `Portfolio`, so its exact method set is specifiable — **now fixed by ADR-0041 §3**.
- **The durability schema/cadence** — what the `Store` persists for the ledger + per-strategy attribution, and snapshot frequency — remains its own ticket (ADR-0034).
- **`PortfolioProjection` is a second projection to recover** — restored from the `Store`, then reconciled against the venue on restart, on the same crash-only path as the order `Cache` (ADR-0009/0034).
